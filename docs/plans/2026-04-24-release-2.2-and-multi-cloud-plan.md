## 1. Goals

1. **Establish `release/X.Y` branch model** — protected per-release branches, `main` reduced to a "where to start" pointer for new contributors.
2. **Adopt validated patterns from the GKE BNK repo** (`/Users/j.lucia/Code/gitlab-f5/terraforms_for_bnk`) — single-source version pinning, Helm OCI login via env vars, Multus declarative patching, scoped FLO RBAC, ipvlan-L3 mode, vendored upstream manifests.
3. **Refactor namespaces** from `f5-operator` monolith to `f5-bnk` (BNK platform) + `f5-utils` (shared infra), matching the GKE convention. Existing deployments unaffected (defaults-only flip).
4. **Make `k8s/` and `bnk/` strictly cloud-agnostic**; `app/` may be cloud-coupled but must declare it via `module.json`. Enforce via CI.
5. **Set up the foundation for multi-cloud** — companion `infra/{gcp,azure,...}/` modules supplying the inputs the agnostic modules need.

These are sequenced so each phase is reviewable and rollbackable in isolation.

## 3. Architecture target

### 3.1 Branch model

```
main                 ← always == HEAD of latest stable release/X.Y (auto fast-forward)
release/2.2          ← protected, PR-only — current BNK 2.2 maintenance
release/2.3          ← protected, PR-only — future BNK 2.3 maintenance
feature/2.2-foo      ← topic branches → PR into release/2.2
feature/2.3-bar      ← topic branches → PR into release/2.3
```

Branch protection rules (configured in GitHub):
- `main`, `release/*` — require PR, require code-owner review, require CI green, no force-push
- `feature/*` — unprotected
- `main` updates only via auto fast-forward from `release/X.Y` after a release tag

Cross-release fix workflow: cherry-pick from one `release/X.Y` to another via PR; never direct push.

### 3.2 Namespace layout

| Namespace | Owner | Contents |
|---|---|---|
| `f5-bnk` | `k8s/bnk-prerequisites` | FLO operator, CNE controller (FLO-deployed), TMM pods (FLO-deployed), CNEInstance CR, F5SPKVlan CRs, NetworkAttachmentDefinitions, IRSA-targeted ServiceAccount |
| `f5-utils` | `k8s/bnk-prerequisites` | FAR pull secret, BNK-issued certs (Certificate from bnk-issuer), shared DaemonSets (node-sysctls, hugepages helpers) |
| `cert-manager` | `k8s/cert-manager` | cert-manager itself — unchanged |
| `<tenant>-<app>` (e.g. `default`, `bnk-demo-client`, `f5-spk-app`) | tenant — NOT module-defaulted | Gateway CR, HTTPRoute, application Deployment + Service, app-specific BNK policies |

### 3.3 Cloud-agnosticism rule

| Layer | Rule | Enforcement |
|---|---|---|
| `infra/{cloud}/` | Cloud-specific BY DESIGN | None needed |
| `k8s/` | **MUST** be cloud-agnostic — no `aws`/`google`/`azurerm` provider | CI gate |
| `bnk/` | **MUST** be cloud-agnostic — same | CI gate |
| `app/` | **MAY** be cloud-coupled — must declare via `module.json` (`cloud_specific`, `supported_platforms`) | CI gate |

### 3.4 TMM data-plane modes

Replace today's `tmm_data_plane_mode = "kernel" | "sriov"` with a fuller enum so all clouds are first-class:

```
tmm_data_plane_mode ∈ {
  "host-device-pci",    # AWS — host-device CNI by PCI bus ID    (today's "kernel", aliased)
  "host-device-name",   # generic — host-device CNI by interface name
  "ipvlan-l3",          # GKE — ipvlan in L3 mode + IPAM
  "ipvlan-l2",          # alternative ipvlan
  "sriov",              # legacy DPDK/vfio-pci (AWS, on-prem, telco/DPU)
}
```

Per-cloud `infra/{cloud}/*` modules supply the right mode + per-mode inputs (PCI bus IDs / interface names / IPAM) via outputs.

`"kernel"` kept as an alias of `"host-device-pci"` for one release; deprecated in `release/2.3`.

### Track D — Cloud-agnosticism enforcement

#### D.1 — `tmm_data_plane_mode` enum expansion

`k8s/network-setup` and `bnk/cneinstance` accept the full mode enum (table in §3.4). Each mode has its own required inputs:

| Mode | Required inputs | Env vars added on TMM |
|---|---|---|
| `host-device-pci` | `external_pci_bus_id`, `internal_pci_bus_id` | `TMM_GENERIC_SOCKET_DRIVER=true`, `TMM_CALICO_ROUTER=default`, `PAL_CPU_SET=0,2`, `TMM_MAPRES_ADDL_VETHS_ON_DP=TRUE`, `ROBIN_VFIO_RESOURCE_1=eth1`, `PCIDEVICE_INTEL_COM_ETH1=<pci>`, `ROBIN_VFIO_RESOURCE_2=eth2`, `PCIDEVICE_INTEL_COM_ETH2=<pci>` (today's AWS) |
| `host-device-name` | `external_iface_name`, `internal_iface_name` | Same minus `PCIDEVICE_*` |
| `ipvlan-l3` | `external_iface_name`, `internal_iface_name`, `external_ipam`, `internal_ipam` | `TMM_DEFAULT_MTU`, `ZEBOS_STATE=legacy` (per GKE) |
| `ipvlan-l2` | Same as `ipvlan-l3` | Same |
| `sriov` | `external_resource_name`, `internal_resource_name` | None added (SR-IOV device plugin allocates) |

Validation block in `variables.tf` errors if the wrong inputs for the chosen mode are missing.

`"kernel"` aliased to `"host-device-pci"` for `release/2.2`; deprecated in `release/2.3`.

#### D.2 — Strip AWS defaults from `k8s/network-setup` + `bnk/cneinstance`

Variables become `default = ""` or `default = null` instead of `default = "0000:00:07.0"`. Per-cloud `infra/{cloud}/*` modules supply the values via wiring.

**Order matters:** ship D.3 (per-cloud outputs) BEFORE D.2 (strip defaults), or fresh deployments break with "missing required value".

#### D.3 — Per-cloud companion outputs

| Cloud | Module | Add outputs |
|---|---|---|
| AWS | `infra/aws/high-performance-nodes` | `external_pci_bus_id` (default `0000:00:07.0`), `internal_pci_bus_id` (default `0000:00:08.0`), `recommended_tmm_data_plane_mode = "host-device-pci"` |
| GCP | NEW: `infra/gcp/multi-vpc-tmm-nodes` | `external_iface_name`, `internal_iface_name`, `external_ipam`, `internal_ipam`, `recommended_tmm_data_plane_mode = "ipvlan-l3"` |
| Azure | NEW: `infra/azure/multi-nic-tmm-nodes` | `external_iface_name`, `internal_iface_name`, `recommended_tmm_data_plane_mode = "host-device-name"` |
| OCP / on-prem | Audit `infra/ocp/`, `infra/ubuntu/` | Add `external_resource_name`, `internal_resource_name`, `recommended_tmm_data_plane_mode = "sriov"` |

The GCP / Azure modules don't exist yet — they're net-new module work and require fresh-cluster validation on the actual cloud. Out of scope for `release/2.2`; targeted at `release/2.3`.

#### D.4 — `app/` cloud-coupling declaration

| Item | Effort |
|---|---|
| Audit every `app/*/module.json` — ensure `cloud_specific` + `supported_platforms` set | Small (~14 modules) |
| `bedrock-smartllm-*` → `cloud_specific: true, supported_platforms: ["aws"]` | Tiny |
| `demo-*` → `cloud_specific: false, supported_platforms: ["any"]` (verify they actually portable) | Small |
| `bnk-forge-v2` filters apps on `supported_platforms` per cluster | Their work — verify with the forge-app agent |

#### D.5 — CI gates

```bash
# .github/workflows/agnosticism.yml (new)

# Layer 1: k8s/ and bnk/ — strict agnostic, no cloud providers
for d in k8s/*/ bnk/*/; do
  if grep -E 'source\s*=\s*"hashicorp/(aws|google|azurerm)"' "$d/versions.tf" 2>/dev/null; then
    echo "FAIL: $d has cloud-specific provider"
    exit 1
  fi
done

# Layer 2: app/ — must declare cloud coupling explicitly
for d in app/*/; do
  meta="$d/module.json"
  if ! jq -e '.module.cloud_specific != null' "$meta" >/dev/null 2>&1; then
    echo "FAIL: $meta missing cloud_specific declaration"
    exit 1
  fi
  if [ "$(jq -r '.module.cloud_specific' "$meta")" = "true" ]; then
    if [ "$(jq -r '.module.supported_platforms[0]' "$meta")" = "any" ]; then
      echo "FAIL: $d declares cloud_specific=true but supports 'any'"
      exit 1
    fi
  fi
done
```
